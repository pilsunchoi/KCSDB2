## 1. 데이터 함정 (실측 확인)

### 1.1 나미비아 ISO2='NA' → pandas NULL 오변환

외교부 국가표준코드 CSV에서 나미비아의 ISO2 코드는 `NA`다. pandas `read_csv`의 기본 `na_values`가 이를 결측(NaN)으로 오변환한다. 처리 없이 dim_country를 만들면 나미비아가 조인 키 결측으로 탈락하고, 관세청이 나미비아를 NA로 집계할 경우 매칭 실패한다.

- 해결: `pd.read_csv(..., keep_default_na=False, na_values=[""])`
- 검증: 이 처리로 iso2 결측 0, 나미비아 'NA' 문자열 정상 보존 확인.
- 계열: 메모리에 기록된 "'NULL' 문자열 리터럴 함정"과 동일 계열(문자열이 결측 토큰으로 오인되는 문제).

### 1.2 관세청 API는 결측과 0을 구분하지 않는다

원본 XML 3종(202401_US, 200701_US, 202401_AD) 전체에서 수치 태그(expDlr/impDlr/expWgt/impWgt/balPayments)는 항상 존재하며, 값이 없으면 0으로 채워져 온다. 결측 태그 0건.

- 귀결: "관측값 없으면 NULL" 원칙은 이 데이터에 적용 불가능. 원본에 NULL이 없다.
- 귀결: `int(값 or 0)`의 `or 0`은 도달하지 않는 방어코드. 결측 손실 아님.
- 202606 프로브 결과가 방증: 미공개월은 items=0(빈 응답)으로 오지, 잠정치를 임의값으로 채우지 않는다.

### 1.3 dim_hs10 한글품목명은 최말단 세분만 담는다

관세청 HS부호 파일의 `한글품목명`은 HS10 최말단 서술만 담는다. 예: `0101211000` = "농가 사육용", `0101291000` = "경주말". 이것이 말(馬)인지 상위 맥락이 없다. 상위 분류는 `성질통합분류코드명`("(말)")에 일부 있으나 불완전.

- 성격: 관세청 파일 자체의 구조적 한계. 파싱·설계 오류 아님.
- 처리: dim_hs10은 이 값을 raw 그대로 담는다. 완전한 품목 서술이 필요하면 상위 HS 코드 조인 또는 HS6 concordance로 분석 계층에서 해결. DB가 서술을 합성하지 않는다.

### 1.4 HS 개정 연계표는 PDF이나 추출 안전

관세청 FTA 포털 HS 연계표 3종은 엑셀이 아니라 150페이지 안팎 PDF. 그러나 2열(HS2022 6자리, 과거 6자리) 순수 코드쌍 구조라 pdfplumber 페이지당 1표로 정확 추출. 병합셀·다단헤더 없음. 형식 이상행 0건(1건 예외는 1.5).

### 1.5 "삭제" 폐지 표기

HS2022→2017 연계표 마지막 페이지에 `(삭제, 300219)` 행 존재. 2017년 코드 300219가 2022에서 폐지되어 대응 코드 없음을 뜻함. 관세청이 폐지 코드를 "삭제" 문자열로 일부 표기.

- 처리: `relation='deleted'`로 보존(제거 아님). 품목 퇴출 정보는 개정 간 품목 연속성을 다루는 분석에서 쓰일 수 있으므로 삭제하지 않는다.
- 다른 두 파일(2007, 2012)에는 삭제 행 없음.

### 1.6 음수 중량 (관세청 사후 정정 원본)

fact_trade에 음수 19행 존재. 전부 중량(exp_wgt/imp_wgt) 음수이고 금액(exp_dlr/imp_dlr)은 0 이상. 관세청의 중량 사후 정정(반품·수정신고로 이전 신고분 중량이 음의 조정치로 상계)이다. 2016년 US에 13행 집중, 나머지 PH·IT·PT·NZ·FR 산발.

- 파싱 오류 아님. 원본 XML에 음수 존재. 02a가 그대로 보존.
- 처리: 원칙(원본 보존)상 보존. 04 검증에서 금액음수(FAIL)와 중량음수(INFO)를 분리. 중량음수는 정상.
- 분석 영향: 단가=금액/중량 계산 시 음수 중량은 이상치. 분석 계층에서 처리.

### 1.7 관세청 월통계 2단계 공개 (잠정월 함정)

관세청은 월 무역통계를 2단계로 공개한다. 먼저 국가별 총계(잠정), 이후 HS10 품목별 확정 명세. 202604·202605는 총계만 나오고 품목 명세가 없는 중간 상태였다.

- 프로브(00_probe)가 "총계 금액>0"으로 판정해 이 두 달을 확정으로 오판했다. 판정 기준을 "품목 명세(item_count>1) 존재"로 수정.
- 02b가 fact_trade에 거래행이 0인 월(잠정월)의 fact_total을 제거. 202604·202605 각 243행, 총 486행 제외.
- 확정 범위: 200701~202603, 231개월.

### 1.8 meta_calls.item_count 결함 (총계행 미집계)

meta_calls.item_count는 수집단계(01_fetch_raw)에서 총계행을 세지 않는다. 거래 0건이나 관세청이 총계행(0값)을 반환한 페어에서 item_count=0이나 fact_total엔 1행 존재. 이런 페어 4,642개 확인.

- 귀결: item_count는 fact 행수의 대조 기준으로 부적합. 총합 비교 시 +/- 페어가 상쇄돼 잔차만 남아 오탐(차이 4) 발생.
- 04 검증 재설계: 총합 비교 폐기. "item_count>0인 페어가 fact에 적재됐는가"(수집→적재 누락 감지)로 방향 전환. 전체 실행에서 미적재 0 확인(PASS).

### 과제 1 — 폐지코드 hs10 품목명 확보

측정 결과와 두 조건부 판단.

측정: 폐지코드(dim_hs10 미매칭 hs10) 4,194종. 거래액 비중 전체 11.6%, 시기별 2007기 21.4%→2022기 0.17%. 집중도: 상위 152종이 거래액 80%, 309종이 90%. 상위 309종 중 308종(99.7%)의 hs6가 concordance 매칭.

자료 제약: data.go.kr은 과거 시점 HS부호 스냅샷을 별도 제공하지 않음(최신본 덮어쓰기). 최신 파일은 폐지코드 미수록. hs10 폐지코드의 정확한 품목명을 담은 공개 기계가독 파일은 현재 미확인. CLIP 과거 관세율표가 남은 경로이나 기계가독성 불확실.

**2026-08-28 해결(자료 확보, dim 미반영).** 남은 경로는 CLIP이 아니라 국가법령정보센터였다.
「관세ㆍ통계통합품목분류표」고시 첨부의 연도별 별표 전문 PDF에 그해 유효한 HS10 전부의 국문·영문
품명이 계층 그대로 들어 있다(§8.1). 2011·2013·2015·2017·2021·2022년 판을 파싱해 고유 HS10
15,255개를 모았고, 폐지코드 4,194종 중 **3,738종(89.1%)**의 품목명이 여기 있다. 거래액으로 보면
폐지코드 거래액의 **94.12%**를 덮고, 남는 미확보 456종은 전체 거래액의 0.68%다. 파싱 결과는
`analysis/HS10 연계표 구축/outputs/byeolpyo_*.csv`에 있다. dim_hs10에 병합할지는 미정 —
관세청 HS부호 파일이 준 값과 기재부 고시가 준 값이 출처가 다르므로, 병합한다면 별도 열이나
별도 테이블로 출처를 구분해야 한다.

조건부 판단:
- HS6 이하 해상도 분석: hs10 세분 품목명은 hs6 절단으로 소거되므로 불필요. hs6 계열 식별은 concordance로 대체(상위 309종의 99.7%). 이 경우 과제 1 불필요.
- HS10 세분 품목명을 쓰는 분석: 품목명 필요. 자료 확보 경로가 막혀 있어 미해결. 필요시 CLIP 조사로 재개.

현 dim에는 근사 품목명을 추가하지 않았다(raw 원칙: 관세청이 그 hs10에 부여한 명칭이 아닌 계열 근사값은 원본 아님).

### 과제 3 — 쿼리 성능 실측: 완료. 인덱스 불필요 확정.

측정(2026-07-03, 로컬 DB 681MB, 27.5M행, 각 쿼리 2회 2번째 채택):

판정: **네 쿼리 모두 인덱스 불필요.**
- 순수 연산은 전부 초 단위 이내(self-join조차 0.9s). Q3·Q4는 0.1~0.4s.

**분석 계층 성능 팁 (DB 결함 아님):**
대용량 결과(수백만 행)를 통째로 파이썬(.df())으로 끌어오지 말 것. 집계를 DuckDB 안에서 완료하고 최종 소형 결과만 가져온다. 예: self-join 후 2천만 행을 넘기지 말고, DuckDB 안에서 추가 집계(국가별·기간별)해 수천 행으로 줄인 뒤 .df(). 이는 쿼리 설계 문제이지 인덱스·DB 구조 문제 아님.

## 8. HS10 연계 세션 (2026-08-28)

배경: `analysis/수출 급성장 탐지와 경기민감도/HS개정_연계표_문제_검토.md`가 "HS10 해상도를 지키려면
관세청 HSK 신구 대비표를 외부에서 들여와야 한다"고 남긴 숙제를 실행했다. 결과는
`dim_hs10_concordance`·`dim_hs10_to_2022` 두 테이블이고, 설계는 DB_구축_원칙.md §3.4에,
구축 기록은 `analysis/HS10 연계표 구축/HS10_연계표_구축.md`에 있다.

### 8.1 HS10 자료의 진짜 소재는 국가법령정보센터다

관세법령정보포털(CLIP)이 아니다. CLIP의 `세계HS개정표`는 세계관세기구 HS6 상관표이고,
`HS비교`는 연도별 관세율표를 나란히 보여줄 뿐 행이 대응되지 않는다. 「관세ㆍ통계통합품목분류표」는
기획재정부(현 재정경제부) 고시이고, 국가법령정보센터 OpenAPI로 인증 없이 연혁 13건과 첨부파일을
받는다.

```
lawSearch.do?OC=test&target=admrul&type=XML&query=관세·통계통합품목분류표&nw=2
lawService.do?OC=test&target=admrul&ID=<행정규칙일련번호>&type=XML
law.go.kr/flDownload.do?flSeq=<첨부일련번호>
```

여기에 연도별 별표 전문(HS10 코드 + 국문·영문 품명, 계층 그대로)이 있다. 폐지코드 품목명 문제
(과제 1)도 이 경로로 풀린다. 가장 옛 고시가 2011년분이라 그보다 이전 판은 없다.

### 8.2 공식 "신구대비표"에는 승계 정보가 없다

2012·2014년 개정 고시에 신구대비표가 첨부돼 있다. 좌우 2단에 `<삭제>`·`<신설>`·`(좌동)`이 찍혀
있어 "이 코드가 저 코드로 갔다"가 적혀 있을 것처럼 보인다. 2012년분 221쪽을 전부 파싱해 4,437행을
뽑아 보니 구성은 폐지 646건, 신설 1,009건, 좌우에 코드가 모두 있는 112건이었고, **그 112건은 전부
좌우 코드가 같다.** 품명만 바뀐 행이다. 승계를 잇는 행은 0건이다.

따라서 HS10 승계표는 어느 기관도 공표하지 않는다. 관세청·기재부가 내는 것은 (ㄱ) HS6 상관표,
(ㄴ) 한-미·한-EU 같은 국가간 10단위 연계표, (ㄷ) 10단위 폐지·신설 목록 셋뿐이다.
**"공식 자료가 있을 것"이라는 전제로 탐색을 시작하면 여기서 멈춰야 한다.**

### 8.3 별표 XLSX는 앞자리 0을 잃는다 (PDF를 쓸 것)

2022년 이후 별표는 XLSX로도 제공된다. 편해 보이지만 쓰면 안 된다. HSK에는 7·9자리 중간 표제가
있어 코드 조각이 `'9'`(9자리 표제)와 `'09'`(10자리)로 갈리는데, 엑셀은 숫자 셀이라 둘 다 9로
저장한다. `'00'`도 0이 된다. XLSX로 파싱한 2022년 HS10은 11,463개가 나왔고, PDF로 파싱하니
**11,293개**로 공식 발표 수치와 정확히 일치했다. PDF에는 자릿수가 문자 그대로 찍혀 있다.

### 8.4 목표 지표를 맞추는 방법은 그 지표로 검증할 수 없다

연계의 목적은 개정 단차(개정 전후 계열 수준의 급단절)를 없애는 것이다. 그런데 채택한
이중비례조정(IPF)은 열합을 개정 직후 수출액에 맞추므로 **단차는 정의상 0이 된다.** 단차 감소를
검증으로 내밀면 순환논법이다.

쓸 수 있는 검증은 **위약 검정**이다. 같은 허용 그래프에 개정이 없는 구간(개정 1년 전 같은 여섯 달
짝)을 물린다. 개정이 없으니 값이 대각선을 떠날 이유가 없고, 그런데도 떠나는 몫이 방법의 잡음
바닥이다. 이 방식으로 재면 2022년 개정은 12.27%p를 옮겼고 잡음은 2.06%였다.

### 8.5 "살아 있는 코드끼리 이동 금지"가 결정적이었다

허용 그래프를 공식 HS6 연계표로만 자르고 돌렸을 때, 위약 구간 대각선 보존율이 83.30%였다.
개정이 없는데도 수출액의 17%가 자리를 옮겼다는 뜻이다. 실제로 디램(8542321010)과 플래시
메모리(8542321030) 사이, 경유(2710193000)와 제트 연료유(2710192020) 사이에 값이 양방향으로 오갔다.
네 코드 모두 개정 전후에 그대로 있는 코드다.

**개정 전후에 모두 살아 있는 서로 다른 코드끼리는 이동을 허용하지 않는다**는 조건 하나를 넣자
잡음이 2.06%로 떨어졌다. 개정이 건드리지 않은 코드는 내용이 오갈 이유가 없다는 당연한 제약인데,
이것을 빼면 조정 단계가 평상시 변동을 전부 "이동"으로 설명해 버린다.

### 8.6 확정치 (2026-08-28)

별표 파싱: 2011년 11,896 / 2013년 12,230 / 2015년 12,240 / 2017년 12,230 / 2021년 12,240 /
2022년 11,293개. 2022년은 공식 수치와 일치, 2021년은 공식 12,242 대비 2개 부족(쪽 경계로 추정).

파서 검증(2012년 공식 대비표 대조): 공식 폐지 646건 중 627건(97.1%)이 2011년 별표에 있고
2013년 별표에는 0건 남음. 공식 신설 1,009건은 100% 2011년 별표에 없음. 역방향으로, 별표 차이로
잡은 폐지 636건 중 627건(98.6%)·신설 970건 중 968건(99.8%)이 공식 목록에 있음.

대각선 보존율(개정 구간 / 위약 구간): 2012년 96.84 / 99.88, 2017년 93.00 / 99.32,
2022년 85.67 / 97.94(%).

테이블: `dim_hs10_concordance` 50,899행, `dim_hs10_to_2022` 75,754행
(chain 66,997 / hs6_fallback 8,757). 가중치 합 이탈 2.2×10⁻¹⁶ 이내.
전 기간(2007~2025) 재집계 총액이 원자료와 일치(오차 0.000%).
연계표 미포함 거래액: 2007기 0.0127%, 2012기 0.0115%, 2017기 0.0099%(수출 기준).

폐지코드 품목명(과제 1): 4,194종 중 3,738종(89.1%) 확보 가능, 폐지코드 거래액의 94.12%.

### 8.7 남은 과제

1. **`method='hs6_fallback'`(8,757행) 구간은 HS10 해상도가 아니다.** 2011년 이전에 사라진 코드로,
   2007~2011년 수출액의 5.61%가 여기 걸린다. HS10 해상도가 필요한 분석은 `method='chain'`만 쓴다.
2. **수출액으로만 조정했다.** 수입·중량 기준 가중치는 다를 수 있다. 수출이 없고 수입만 있는
   코드는 사실상 품명 유사도가 그대로 가중치가 된다.
3. **국가별 자료에 미적용.** 목적지 수·확산·집중도는 국가×HS10 수준 지표라 코드 수준 가중치를
   그대로 써도 되는지 확인이 필요하다.
4. **폐지코드 품목명의 dim 반영 미정.** 출처가 관세청 HS부호 파일이 아니라 기재부 고시이므로,
   병합한다면 출처를 구분할 열이나 별도 테이블이 필요하다.
