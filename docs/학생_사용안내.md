# 학생 사용 안내 — KCSDB2 무역통계 DB

이 DB는 관세청 무역통계(2007년 1월부터 최신 확정월까지)를 분석용으로 가공한 것이다.
정확한 범위와 행수는 `python scripts/06_db_status.py`로 확인한다.
로컬 주피터 노트북에서 분석한다.

---

## 1단계 — 패키지 설치

터미널(명령 프롬프트/PowerShell/터미널)에서:
```
pip install duckdb pandas matplotlib jupyter
```
재구축이 아니라 분석만 하므로 이 4개면 충분하다. conda·특정 파이썬 버전 불필요.

---

## 2단계 — 저장소 받기

GitHub에서 이 저장소를 clone 또는 ZIP 다운로드 후 압축 해제.

---

## 3단계 — DB 받아서 배치

저장소에는 DB가 없다(GitHub 100MB 한도 초과). **Releases 페이지**에서 압축된 DB
(`kcsdb.duckdb.gz`)를 받아 압축을 풀고 `data/processed/kcsdb.duckdb`에 놓는다.

압축 해제:
- Windows: 7-Zip 등으로 .gz 해제
- Mac/Linux: `gunzip kcsdb.duckdb.gz`

---

## 4단계 — 주피터 실행

저장소 루트에서:
```
jupyter notebook
```
브라우저가 열리면 `notebooks/analysis_start.ipynb`를 연다.
셀을 위에서부터 실행하면 접속·구조 확인·기술통계 시연이 순서대로 나온다.
5절은 아래 함정 가운데 가장 자주 걸리는 HS 개정 연결을 6자리·10자리 두 방식으로 실습한다. 10자리 연계표 적용, 전 기간 변환, 개수 지표에서 안분 대신 최빈 승계를 쓰는 법, 폐지코드 품명 조회가 모두 실행 가능한 코드로 들어 있다.

---

## DB 구조 (분석 시작 전 필독)

- **fact_trade**: 거래(국가×HS10×월). yyyymm, stat_cd, hs10, exp_dlr, imp_dlr, exp_wgt, imp_wgt, bal_payments
- **fact_total**: 국가×월 총계. HS 없음.
- **fact_nqi**: 신성질별×국가×월 수출입 실적(**2005.01~**, 이 표만 더 길다). 관세청이 직접 집계한 공식치라 HS 개정을 건너뛴 계열이 필요할 때 쓴다. `dim_hs10_to_nqi`로 `fact_trade`를 환산한 값과 달리 추정이 섞이지 않는다 — 환산치는 총액은 맞지만 세세분류 배분이 옛 연도에서 어긋난다(`mart_nqi_check` 참조). **`fact_trade`와 더하면 안 된다.** 같은 무역을 다른 분류로 집계한 것이다
- **dim_country**: stat_cd → 국가명·ISO·대륙
- **dim_hs10**: hs10 → 품목명·단위·발효일
- **dim_hs6_concordance**: HS 개정 간 연결, 6자리(hs2022 ↔ 과거코드). 관세청 공식 연계표
- **dim_hs10_to_2022**: HS 개정 간 연결, 10자리(과거코드 → hs2022 + 가중치). 공식 자료가 없어 **추정한 것**
- **dim_hs10_concordance**: 개정 하나(2012·2017·2022)를 건너는 10자리 연결. 위 표의 재료
- **dim_hs10_name_hist**: HS10 품명 이력(hs10 × 별표연도). **dim_hs10에 이름이 없는 폐지코드는 여기서 찾는다**
- **dim_nqi**, **dim_hs10_to_nqi**: 관세청 신성질별 분류 758개와 HS10 대응. 개정에 흔들리지 않는 안정적 분류라 긴 시계열에 좋다. 대신 해상도가 낮다
- **dim_hs10_to_major10**: HS10 → 10대 수출품목(반도체·승용차 등). 관세청 공표치와 대조해 확정
- **fact_exp10d**, **v_exp10d_seg**: 10일 단위 잠정치(2016.01~). 네 계열이 들어 있고 `series`로 가른다 — `exp_item`(수출 품목별) · `exp_cnty`(수출 국가별) · `imp_item`(수입 품목별) · `imp_cnty`(수입 국가별). 월 자료보다 빠르지만 중량이 없고 항목이 열 개씩뿐이다. **뷰를 쓸 때 `series`를 반드시 거를 것** — 안 그러면 품목과 국가가 섞여 총계가 두 배가 된다
- **dim_workday10d**: 상순·중순·하순의 조업일수. 10일 단위 자료를 견주려면 반드시 함께 쓴다
- **mart_...**: 이 저장소가 계산해 둔 지표다(받은 자료가 아니다). `mart_exp10d_*`는 10일 자료의 조업일수 보정·기여도·월 마감 예측, `mart_nqi_check`는 신성질별 공식치와 환산치의 대조다. **접두어가 `mart`면 우리가 만든 것**이라는 뜻이니 그대로 인용하기 전에 근거를 확인할 것

금액 단위: 미화 달러(USD). 중량 단위: kg.

## 분석 시 반드시 알아야 할 함정 (docs/세션_발견_노트.md 상세)

- **HS 개정 연결**: 2022 개정으로 코드가 바뀐 품목은 코드 동일성만으로 시계열이 끊긴다.
  8524122000(평판 디스플레이 모듈)은 원자료에서 2022년 1월에 무에서 생겨나는 것처럼 보이지만,
  실제로는 8517701023 등에서 옮겨 온 물량이다. 2022년 개정 하나로 수출액의 13~14%가 코드를 옮겼다.
  - 6자리로 충분한 분석: `dim_hs6_concordance`로 hs6를 통일한 뒤 수행한다.
  - 10자리가 필요한 분석: `dim_hs10_to_2022`를 조인하고 금액에 `weight`를 곱한 뒤 `hs2022`로 다시
    집계한다. `past_version`은 2011년까지 '2007', 2012~2016년 '2012', 2017~2021년 '2017'을 쓰고,
    2022년 이후 자료는 이미 현행 체계이므로 변환하지 않는다. **`method='chain'`으로 걸러야
    10자리 해상도가 유지된다**(`hs6_fallback`은 6자리로 흩뿌린 보완분이다).
  - 다만 10자리 연계는 공식 자료가 아니라 추정이다. 나뉜 비율은 개정 직후 6개월 수출액에서
    계산한 값이지 관세청이 알려 준 값이 아니다. 논문에 쓸 때는 이 점을 밝힌다.
- **음수 중량 19행**: 관세청 사후 정정 원본. 단가(금액/중량) 계산 시 이상치.
- **범위 경계**: 월 실적은 최신 확정월까지이고 마지막 해는 부분년이므로 연도끼리 견줄 때는 제외한다. `SELECT MIN(yyyymm), MAX(yyyymm) FROM fact_trade`로 확인한다.
- **폐지코드**: hs10의 27.2%는 dim_hs10에 품목명이 없다(폐지코드). HS6 수준 분석은 무영향. 이름이 필요하면 `dim_hs10_name_hist`에서 얻는다(폐지코드의 89.1%, 거래액 94.1%를 덮는다).
- **품명은 변한다**: 같은 코드인데 판본에 따라 품명이 다른 경우가 31.5%다(젖소→번식용, 우모분→깃털가루). `dim_hs10_name_hist`는 `byeolpyo_year`별로 원문을 그대로 담으므로, 한 이름만 필요하면 가장 최근 판본을 골라 쓴다.
