# 후속 세션 업로드 안내

작성일: 2026-07-03
목적: 다음 세션에서 KCSDB2 작업 시 무엇을 올려야 하는가. 목적별로 다르다.

---

## 절대 제약

**kcsdb.duckdb(676MB)는 채팅 인터페이스에 업로드 불가능하다. 크기 한도 초과.**
DB 내용이 필요하면 로컬에서 쿼리 실행 후 결과를 붙여넣는다. DB 실물은 어느 경우에도 올리지 않는다.

---

## 공통 필수 (어느 목적이든 반드시)

- **docs/세션_발견_노트.md** — 0절 판정 봉인 포함. 안 올리면 다음 AI가 커버리지 WARN(72.8%, 66/71/80%)을 결함으로 재지적한다. 재발 방지의 핵심.
- **docs/DB_구축_원칙.md** — 설계 헌법. 안 올리면 fact에 파생 컬럼 추가·분석 개념 DB 삽입 같은 원칙 위반 제안이 나온다.

두 파일 다 텍스트라 가볍다. 무조건 올린다.

**준필수: README.md** — 전체 테이블 스키마·파일 구성 정리. 다음 AI가 DB 구조를 빠르게 파악. 텍스트라 가벼움. 올릴 가치 있음.

---

## 목적별 추가

### 경우 A — DB 내용 질의·분석 (extensive margin 계산 등)
- 공통 필수 2개 + (DB 실물은 못 올림)
- 방식 1: 로컬에서 쿼리 실행 → 결과 붙여넣기 (이 세션에서 쓴 방식)
- 방식 2: 분석 단위로 집계한 소형 CSV만 추출해 업로드 (전체 27.5M행 아님)

### 경우 B — 스크립트 수정·확장 (분석 스크립트 작성 등)
- 공통 필수 2개 + 수정 대상 스크립트만
- 예: concordance 조인 로직 → 03b(스키마 확인용) + README(전체 스키마)

### 경우 C — 파이프라인 재실행·업데이트 (신규 월 수집 등)
- 공통 필수 2개 + 파이프라인 코어 6개(00, 02a, 02b, 03, 03b, 04)
- 이 6개는 KCSDB2_final.zip에 있으므로 zip 하나로 갈음
- 실제 실행은 로컬. AI는 스크립트 수정·제공만.

## 최소 조합 요약

거의 모든 후속 세션: **세션_발견_노트.md + DB_구축_원칙.md** (+ README.md 준필수).
여기에 목적별로 스크립트 일부(B·C) 또는 로컬 쿼리 결과(A)를 더한다.
DB 실물은 올리지 않는다 — 로컬 실행 결과로 우회.
