# 배포자 안내 — DB를 GitHub Releases로 배포하기

이 문서는 **DB를 배포하는 사람(교수/관리자)**용이다. 학생용은 docs/학생_사용안내.md.

---

## 배경

DB 실물(kcsdb.duckdb, ~681MB)은 GitHub 저장소 파일 한도(100MB)를 초과한다.
저장소에는 코드·문서만 올리고(.gitignore가 data/processed 제외), DB는 **Releases 첨부**로 배포한다.
Releases는 파일당 2GB까지 허용한다.

---

## 1단계 — DB 압축

로컬에서 실행. 무역 데이터는 반복이 많아 압축률이 높다.

Windows(PowerShell) 또는 Git Bash:
```
cd C:\Work\Projects\KCSDB2\data\processed
# gzip 방식 (학생이 .gz를 받아 압축 해제)
python -c "import gzip,shutil; f=open('kcsdb.duckdb','rb'); g=gzip.open('kcsdb.duckdb.gz','wb',compresslevel=9); shutil.copyfileobj(f,g); g.close(); f.close(); print('done')"
```

압축 후 크기를 확인한다. 100MB 미만이면 저장소에 직접 넣을 수도 있으나, 안정성을 위해 Releases 권장.

---

## 2단계 — GitHub 저장소 준비

1. 저장소 생성(공개). 기존 https://github.com/pilsunchoi/KCSDB 를 갱신하거나 KCSDB2로 신규.
2. .gitignore가 다음을 제외하는지 확인: `data/raw/`, `data/processed/`, `config/api_key.env`, `__pycache__/`
   (DB·원본·인증키가 저장소에 올라가면 안 됨)
3. 코드·문서·외부자료·노트북을 커밋·푸시.
   - scripts/, docs/, notebooks/, data/external/, README.md, requirements.txt
   - data/external/ 은 라이선스상 재배포 가능(README 출처 절 참조). 용량이 작아 저장소에 포함 가능.

---

## 3단계 — Release 생성 및 DB 첨부

1. 저장소 → Releases → "Draft a new release"
2. 태그 지정: 데이터 시점 명시. 예: `v1.0-202603` (2026.03까지 데이터)
3. 제목·설명에 **데이터 범위와 출처**를 명시:
   ```
   KCSDB2 v1.0 — 관세청 무역통계 2007.01–2026.03
   출처: 관세청 품목별 국가별 수출입실적(data.go.kr, 15100475),
        외교부 국가표준코드(15091117), 관세청 HS부호(15049722, 공공누리 1유형),
        관세청 FTA포털 HS연계표(공공누리 1유형)
   ```
4. `kcsdb.duckdb.gz`를 드래그해 첨부.
5. Publish.

---

## 4단계 — 학생 배포 확인

학생은 `notebooks/analysis_start.ipynb`를 로컬 주피터에서 연다. 이 노트북은 DB를
`data/processed/kcsdb.duckdb`에서 읽으므로, 학생이 Release에서 받은 DB를 그 경로에
놓으면 된다. 배포자가 URL을 노트북에 넣을 필요는 없다(학생이 수동 배치).

학생 안내는 docs/학생_사용안내.md에 있다. Release 설명에 이 문서를 안내한다.

---

## 갱신 시 (신규 월 데이터 추가 후)

1. 로컬에서 파이프라인 재실행(00 프로브 → 신규월 수집 → 02a~04).
2. 새 DB 압축.
3. **새 Release**를 새 태그로 생성(예: v1.1-202606). 기존 Release는 남겨둔다(학생 재현성).
4. 학생은 새 Release에서 DB를 받아 data/processed/ 에 교체한다.

---

## 라이선스 준수 (필수)

- README의 "데이터 출처 및 라이선스" 절을 반드시 유지.
- HS부호·HS연계표는 공공누리 제1유형: 출처표시 위반 시 이용허락 자동 종료.
- Release 설명에도 출처 명시(위 3단계).
- 공공기관이 후원·특수관계인 것처럼 오인시키는 표시 금지.
