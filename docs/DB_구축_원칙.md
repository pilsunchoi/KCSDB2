# KCSDB 구축 원칙

작성일: 2026-07-03
대상: 관세청 무역통계 DB 재구축 (KCSDB2)
목적: 이 문서는 재구축의 설계 헌법이다. 모든 스크립트는 이 원칙을 따른다. 원칙과 코드가 충돌하면 코드를 고친다.

---

## 0. 최상위 원칙

DB는 관세청 원본을 최대한 그대로 담는다. 분석을 위한 가공은 DB가 아니라 분석 계층에서 한다.

이 원칙을 세 문장으로 압축한다.

1. fact 테이블은 관세청 API 응답 필드만 담는다. 파생 컬럼을 만들지 않는다.
2. 관측값을 변형하지 않는다. 관세청이 준 값을 그대로 저장한다.
3. 시계열 연결(HS 개정, 국가코드)과 참조 정보(국명, 품목명)는 dim 테이블에서 제공하되, fact는 건드리지 않는다.

---

## 1. 원본 XML 구조 (2026-07-03 실측 확인)

재구축의 모든 판단은 실제 XML 구조에 근거한다. 세 표본(202401_US 6,415행, 200701_US 5,532행, 202401_AD 7행)을 확인한 결과는 다음과 같다.

### 1.1 태그 구조

모든 item은 10개 태그를 가진다. 예외 없다.

```
balPayments, expDlr, expWgt, hsCd, impDlr, impWgt,
statCd, statCdCntnKor1, statKor, year
```

- `year` = "총계" → 총계 행 (국가-월 집계)
- `year` = "YYYY.MM" → 거래 행 (HS10 품목별)

### 1.2 결측 처리 (중요)

**관세청 API는 결측과 0을 구분하지 않는다.** 수치 태그(expDlr, impDlr, expWgt, impWgt, balPayments)는 항상 존재하며, 값이 없으면 `0`으로 채워져 온다. 세 표본 전체에서 결측 수치 태그는 0건이다.

따라서 "관측값 없으면 NULL, 0이면 0"이라는 구분은 이 데이터에서 원천적으로 불가능하다. 원본에 NULL이 존재하지 않기 때문이다. 관세청이 이미 "거래 없음 = 0"으로 인코딩한다.

**결론: 정수 캐스팅 `int(값)`은 손실이 아니다. 뭉갤 결측 자체가 없다.** 이전 KCSDB(v1)에서 `int(d.get("expDlr") or 0)`를 결측 손실로 지적했으나, 이는 철회한다. `or 0`은 도달하지 않는 방어 코드일 뿐이다.

### 1.3 0값 행의 보존

관세청은 다음 행들도 응답에 포함시킨다. 모두 raw로 보존한다.

- 수출만 0, 수입 양수 (또는 그 반대)
- **수출·수입 금액 모두 0인 거래 행** (202401_US 4건, 200701_US 1건 확인). 관세청이 이런 행을 왜 포함하는지는 불명이나, 원본에 있으므로 제거하지 않는다.
- `expWgt=0`인데 `expDlr>0`인 행 (202401_AD의 3304991000: expDlr=65, expWgt=0). 소액 거래에서 kg 미만이 반올림돼 중량이 0이 된 경우. **이 행은 분석 시 `단가=금액/중량` 계산을 불가능하게 만든다.** 그러나 이것은 분석 계층의 제약이지 DB의 결함이 아니다. DB는 (65, 0)을 그대로 보존한다.

### 1.4 총계 행의 특수성

총계 행은 `statCd=-`, `hsCd=-`, `statCdCntnKor1=-`, `statKor=-`로 온다. 국가코드가 응답에 없다.

- 총계 행의 `stat_cd`는 **파일명에서 추출**한다 (파생값). fact_total.stat_cd는 응답 원본(-)이 아니라 파일명 유래임을 문서에 명시한다.
- 이것이 유일하게 허용하는 "파생"이다. 총계 행에 국가코드를 붙이지 않으면 어느 국가의 총계인지 알 수 없기 때문이다.

### 1.5 후행 공백

초기 연도(200701)의 `statKor`에 후행 공백이 있다 (`"경주말 "`). 2024년에는 없다. `.strip()`은 dim 테이블에 저장할 때만 적용한다. 원본 XML은 그대로 보존한다.

## 2. fact 테이블 설계

### 2.1 fact_trade (거래 행)

관세청 API 응답 필드만. 파생 컬럼 없음.

| 컬럼 | 출처 | 비고 |
|------|------|------|
| yyyymm | 파일명 | 호출 시기. 응답의 year(YYYY.MM)와 일치 검증 |
| stat_cd | 응답 statCd | 관세청 원본. 변형 없음 |
| hs10 | 응답 hsCd | 관세청 원본. 변형 없음 (strip만) |
| exp_dlr | 응답 expDlr | 관세청 원본 |
| imp_dlr | 응답 impDlr | 관세청 원본 |
| exp_wgt | 응답 expWgt | 관세청 원본 |
| imp_wgt | 응답 impWgt | 관세청 원본 |
| bal_payments | 응답 balPayments | 관세청 원본. exp_dlr-imp_dlr과 항등이나 API가 주는 값이므로 보존 |

**제거하는 컬럼 (v1 대비):**
- `year`, `month` — yyyymm에서 파생. 만들지 않는다.
- `hs2`, `hs4`, `hs6` — hs10 슬라이싱 파생. dim_hs10에서 JOIN으로 얻는다.
- `stat_kor` — 국가 한국어명. dim_country에서 얻는다.
- `stat_kor_item` — 품목 한국어명. dim_hs10에서 얻는다.

**bal_payments 보존 판단:** exp_dlr-imp_dlr과 정확히 일치하는 파생값이다. 그러나 관세청 API가 원래 제공하는 필드이므로 raw 충실성 원칙에 따라 보존한다. "파생 컬럼을 만들지 않는다"는 원칙은 *우리가 계산해 넣는* 컬럼에 적용된다. 관세청이 준 것은 보존한다.

### 2.2 fact_total (총계 행)

| 컬럼 | 출처 | 비고 |
|------|------|------|
| yyyymm | 파일명 | |
| stat_cd | **파일명** | 응답은 `-`. 파일명 유래 파생 (유일 허용 파생) |
| exp_dlr | 응답 expDlr | |
| imp_dlr | 응답 impDlr | |
| exp_wgt | 응답 expWgt | |
| imp_wgt | 응답 impWgt | |
| bal_payments | 응답 balPayments | |

fact_total은 국가-월 집계만 담는다. HS 컬럼 없음.

## 3. dim 테이블 설계

fact가 raw인 대신, 모든 연결·참조·교정은 dim이 담당한다.

### 3.1 dim_country

관세청 stat_cd를 키로 하고, 외교부 표준명을 **참조로** 붙인다. fact는 어느 경우든 관세청 raw를 유지한다.

- `stat_cd` (PK) — 관세청 원본 코드
- `name_ko_kcs` — 관세청 응답 한국어명 (원본 보존)
- `name_ko_mofa`, `name_en`, `iso2`, `iso3`, `iso_num` — 외교부 참조
- `continent_*` — 대륙 참조

**교정 정책:** 관세청 코드가 외교부 표준에 매칭되지 않으면 참조 컬럼은 NULL로 둔다 ("없으면 없는 대로"). 관세청 고유 코드(EU 등)가 여기 해당한다. 국가명 오타 교정은 하지 않는다. 외교부 표준명을 **별도 컬럼으로 병기**하는 것으로 교정을 대신한다. 원본(name_ko_kcs)은 훼손하지 않는다.

### 3.2 dim_hs10

관세청 HS부호 파일(관세청_HS부호_YYYYMMDD.xlsx)로 품목명·단위·발효일을 채운다.

- `hs10` (PK)
- `description_ko`, `description_en` — 관세청 품목명
- `unit_qty`, `unit_wgt` — 수량단위코드, 중량단위코드
- `valid_from` — 적용시작일자 (실측). v1의 근사적 버전 태깅(1.1 일괄 가정)을 실측 발효일로 대체
- `first_yyyymm`, `last_yyyymm` — fact_trade에서 관측된 등장 범위

**한계:** 관세청 HS부호 파일(2026 기준)은 2026년 유효 코드만 담는다. 폐지 코드가 없다. 2007-2021에만 존재하다 폐지된 HS10은 이 파일과 매칭되지 않아 description이 NULL이 된다. 이는 "정직한 NULL" 정책으로 수용한다. 폐지 코드 품목명이 필요하면 §3.5의 `dim_hs10_name_hist`를 쓴다(2026-08-28 추가. 관세청 과거 파일이 아니라 기획재정부 고시 별표에서 얻었다).

### 3.3 dim_hs6_concordance (신규, 시계열 연결의 핵심)

HS 개정 간 대응을 담는다. 이것이 매 분석마다 반복할 수 없는 연결 작업을 DB 계층에서 한 번 해결하는 테이블이다.

- 단위: **HS6** (국제표준, 공식 연계표 공개됨)
- 출처: 관세청 FTA 포털 HS 연계표 (아래 3개 PDF, 2026-07-03 확보)
- 구조: (hs2022, hs_past, past_version) — **다대다 매핑**
- 용도: 개정을 걸친 HS6 시계열을 안정 코드로 연결

**확보한 자료 (data/external/):**
- HS연계표_2022to2007.pdf (154p, 6,592쌍, 변경 1,924)
- HS연계표_2022to2012.pdf (150p, 6,415쌍, 변경 1,422)
- HS연계표_2022to2017.pdf (139p, 5,936쌍, 변경 694)

출처 URL (fileKey 기반, 세션 만료 가능하므로 원본 보존):
- 2022→2007: nttFileDownload.do?fileKey=baee47db73be787e49c4e253fc2f5c23
- 2022→2012: nttFileDownload.do?fileKey=44117257ba1e58e075bc9b4ddb851897
- 2022→2017: nttFileDownload.do?fileKey=da55980b75d6a9f5020d6770db37acf7
- 페이지: customs.go.kr/ftaportalkor/cm/cntnts/cntntsView.do?mi=3397&cntntsId=1059

**형식:** PDF지만 2열(HS2022 6자리, 과거 6자리) 순수 코드쌍. pdfplumber로 페이지당 1표 정확 추출. 병합셀·다단헤더 없음.

**구조적 특성 — HS2022 허브 스타형:** 세 파일 모두 HS2022를 기준으로 과거 각 버전에 대응한다. HS2022→2007 파일이 가장 먼 구간을 덮으므로, 세 파일 결합 시 2007~2022 전 구간 연결이 가능하다. "2012↔2007 직접 대응이 없다"는 우려는 해소됨.

**다대다 관계 (핵심 제약):** 1:1 치환 불가능하다. HS2022→2007 기준, 하나의 2022 코드가 여러 2007 코드에 대응(분할 역방향) 301건, 여러 과거 코드가 한 2022 코드로 통합 574건. 예: 010130(2022) → 010110, 010190(2007) 둘 다 대응.
- **DB 계층:** concordance 테이블은 다대다를 그대로 보존한다. 규칙을 부과하지 않는다.
- **분석 계층:** 시계열 집계 시 연결 컴포넌트(같은 상품군으로 묶이는 코드 집합)를 계산해 처리한다. 이 처리는 DB 밖에서 한다.

**한계 — HS2022 스타형의 사각지대:** 2007에 있다가 HS2022에서 완전 소멸한 코드는 세 파일 어디에도 없을 수 있다(2022 대응점이 없어서). 재구축 시 fact의 HS6 중 세 연계표 어디에도 안 나타나는 코드를 목록화해 규모를 측정한다.

**HS10이 아니라 HS6인 이유 (2026-07-03 판단):**
1. 공식 연계표가 HS6까지만 공개된다 (FTA 원산지 용도).
2. 경제 분석(수출 변동 분해, granularity, margin 분해)의 사실상 표준 해상도가 HS6다.
3. HS10 다대다 매핑은 자료 접근이 불확실하고 규칙 설계가 복잡하다. raw+최소연결 원칙에서 벗어난다.

> **2026-08-28 갱신.** 1·2는 그대로 유효하다. 3은 해소됐다. 자료 접근 경로(국가법령정보센터
> 고시 첨부 별표 전문)를 찾았고 규칙도 설계했다. §3.4가 그 결과다. **다만 §3.4는 §3.3을
> 대체하지 않는다.** HS6 연계는 공표된 사실이고 HS10 연계는 추정이다. 성격이 다르므로 두
> 테이블을 따로 둔다.

**설계 결과:** fact는 HS10 raw를 보존하고, 개정 연결은 HS6 concordance로 별도 제공한다. 분석 시 HS10→HS6 절단 후 concordance로 시계열을 잇는다. 절단은 분석 계층에서 수행한다 (`SUBSTR(hs10,1,6)`).

### 3.4 dim_hs10_concordance · dim_hs10_to_2022 (2026-08-28 추가)

#### 왜 필요한가

§3.3의 HS6 연계로 개정을 걸친 시계열을 이을 수 있다. 그런데 HS6로 올리면 잃는 것이 있다.
한국 자료의 품목 구분은 6,090개(HS6)가 아니라 15,403개(HS10)이고, 라면(1902301010)이나
김치(2005991000) 같은 개별 품목은 6자리로 자르는 순간 상위 분류에 묻힌다. HS10 해상도가
필요한 분석은 개정을 못 건넌다.

문제의 크기는 실측돼 있다. 2022년 개정만으로 **수출액의 13~14%가 새 코드로 옮겨 갔다.**
8542324030(메모리형 복합부품 집적회로)은 2017~21년 누적 446.8억 달러를 찍고 2021년 12월에
사라지며, 같은 물건이 2022년 1월 신설된 8542324000에서 다시 시작한다. 8517701023(통신기기
부분품, 누적 323.4억 달러)의 물량은 8524122000(평판 디스플레이 모듈)으로 넘어간다. 자료에는
이것이 하나의 흐름이 아니라 서로 무관한 두 계열로 들어 있다.

특히 **개수 기반 지표는 이 오염에 취약하다.** 목적지 수·확산·집중도처럼 코드를 세는 지표는
개정 신설 코드에서 값이 왜곡된다. 신생 코드는 확산 지표 백분위 0.919·증가율 0.855에 앉는데,
이는 실적이 아니라 코드가 새것이기 때문이다(`analysis/수출 급성장 탐지와 경기민감도/
HS개정_연계표_문제_검토.md` 참조). 이것이 §3.3의 봉인 2 예외 조건에 해당하는 사례다.

#### 자료 — 공식 HS10 승계표는 존재하지 않는다

관세법령정보포털(CLIP)의 `세계HS개정표`는 세계관세기구의 HS6 상관표이고, `HS비교`는 연도별
관세율표를 나란히 보여줄 뿐 행이 대응되지 않는다. 관세청이 내는 "연계표"는 HS6이거나
한-미·한-유럽연합 같은 국가간 10단위다. 기획재정부 고시 첨부의 2012·2014년 신구대비표도
폐지 목록·신설 목록·품명변경뿐이고, 좌우에 코드가 모두 있는 112건은 전부 좌우가 같은 코드다.
**승계를 잇는 행은 한 건도 없다.**

대신 **연도별 별표 전문**을 국가법령정보센터에서 받을 수 있다. HS10 코드와 국문·영문 품명을
계층 그대로 담은 PDF다. 인증 없이 OpenAPI로 접근한다.

```
lawSearch.do?OC=test&target=admrul&type=XML&query=관세·통계통합품목분류표&nw=2
lawService.do?OC=test&target=admrul&ID=<행정규칙일련번호>&type=XML
law.go.kr/flDownload.do?flSeq=<첨부일련번호>
```

#### 절차 (scripts/03c_build_hs10_concordance.py)

1. **별표 파싱.** PDF에는 격자선이 없지만 열 x좌표가 고정이다. 낱말의 성격(숫자/한글/로마자)으로
   갈라 각 무리의 최빈 x를 열 기준으로 삼고, 줄을 y로 묶어 HS4 열에 낱말이 있는 줄에서 새
   레코드를 연다. 판본마다 좌표가 몇 pt씩 흔들리므로 고정 허용오차가 아니라 이웃 열의 중간점을
   경계로 쓴다. 계층 경로 품명(부모 품명을 뿌리부터 이어 붙인 문자열)도 여기서 만든다.
2. **개정 전후 비교.** 두 판의 HS10 집합을 비교해 존속·소멸·신설을 가른다.
3. **허용 그래프.** (개정 전 코드 p, 개정 후 코드 t) 쌍 가운데 두 조건을 만족하는 것만 후보로 둔다.
   첫째, `dim_hs6_concordance`가 p의 6자리를 t의 6자리로 이어 주어야 한다. **국가 재량인 뒤 4자리는
   6자리 이동을 따라가므로 공식 자료로 후보를 자를 수 있다.** 둘째, 개정 전후에 모두 살아 있는
   서로 다른 코드끼리는 이동을 막는다. 양쪽에 다 있는 코드는 개정이 건드리지 않은 것이므로 내용이
   오갈 이유가 없고, 열어 두면 다음 단계가 평상시 변동까지 이동으로 빨아들인다.
4. **사전가중.** 잎 품명과 계층 경로 품명의 유사도를 6:4로 섞어 8제곱한다. 10자리 품명은 '기타'가
   태반이라 그 자체로는 변별력이 없고, 반대로 경로만 쓰면 같은 호 아래에서 앞부분이 길게 겹쳐
   '자동차 휘발유'와 '나프타'가 같은 점수를 받는다. 같은 코드끼리는 유사도를 1로 둔다.
5. **이중비례조정(IPF).** 행합을 개정 직전 6개월 수출액에, 열합을 직후 6개월 수출액에 번갈아
   맞춘다(400회). 허용 그래프 위에서만 움직이므로 이동한 만큼만 대각선에서 떨어져 나간다.
   살아남은 코드가 내용의 일부만 잃는 경우도 이 단계에서 처리된다.
6. **연쇄 구성과 HS6 보완.** 세 개정을 이어 곱해 과거 체계 → 2022 체계 표를 만든다. 2011년 이전에
   사라진 코드는 별표가 없어 연쇄에 못 드므로, 공식 HS6 연계표가 허용하는 현행 6자리로 보내고
   그 안에서는 2022년 교역액 비중으로 나눈다(`method='hs6_fallback'`).

#### 테이블

- `dim_hs10_concordance` (50,864행) — 개정 하나를 건너는 표.
  (hs_from, hs_to, revision, weight, score, relation). revision은 2012·2017·2022.
  weight는 hs_from별 합이 1. relation은 identity/moved.
- `dim_hs10_to_2022` (75,719행) — 과거 체계를 현행 위로 한 번에 옮기는 표.

4. **2011년 이전에 사라진 코드는 HS6 해상도로만 잇는다.** 2007~2011년 수출액의 5.61%가 여기

5. **국가별 자료에는 아직 적용해 보지 않았다.** 목적지 수·확산·집중도는 국가×HS10 수준에서

### 3.5 dim_hs10_name_hist (2026-08-28 추가)

#### 왜 필요한가

§3.2가 남긴 한계다. 관세청 HS부호 파일은 2026년 유효 코드만 담아, 2007~2021년에만
존재하다 폐지된 HS10 4,194종의 품명이 NULL이다(커버리지 72.8%). 세션 발견 노트의
과제 1이 이것이고, "과거 시점 HS부호 스냅샷은 data.go.kr에 없다"는 이유로 미해결로
남아 있었다. §3.4에서 확보한 별표 전문에 그해 유효했던 코드 전부의 품명이 있으므로
이 문제가 풀린다 — **4,194종 중 3,738종(89.1%), 폐지코드 거래액의 94.12%.**

#### 왜 dim_hs10에 열로 넣지 않는가

**품명이 판본에 따라 변하기 때문이다.** 별표 여섯 판을 맞대면 15,255종 가운데
**4,806종(31.5%)이 판본별로 다른 품명을 갖는다.** 표기를 다듬은 것만이 아니다.

| 코드 | 옛 품명 | 뒤 품명 |
|---|---|---|
| 0102901000 | 젖소 | 번식용 |
| 0104201000 | 유용산양 | 젖염소 |
| 0505901000 | 우모분 | 깃털가루 |
| 0506902000 | 골분 | 뼛가루 |

`dim_hs10`의 키는 `hs10` 하나다. 시간에 따라 변하는 값을 여기에 열로 넣으면 여러
참값 가운데 하나를 임의로 고르고 나머지를 버리는 것이 된다. 어느 해에 품명이 바뀌었는지는
품목을 추적하는 분석에 필요한 사실이므로 버려서는 안 된다.

§3.1의 dim_country 병기 선례(관세청 국명 + 외교부 표준명)는 **시간축이 없는 경우**였다.
한 국가코드의 두 이름은 동시에 참이다. 여기는 다르므로 같은 처방을 쓸 수 없다.

**설계 결과:** `dim_hs10`은 건드리지 않는다. 관세청이 준 값과 그 NULL을 그대로 두어
"정직한 NULL" 정책을 유지하고, 기존 쿼리도 깨지지 않는다. 품명 이력은 (hs10, 별표연도)를
키로 하는 별도 테이블에 원본 그대로 쌓는다.

#### 테이블

`dim_hs10_name_hist` (72,129행, 고유 HS10 15,255종)
(hs10, byeolpyo_year, name_ko, name_en). 전문 별표가 있는 여섯 해(2011·2013·2015·2017·
2021·2022)를 담는다. 2012·2014년 판은 신구대비표라 전문이 아니므로 제외한다.

출처가 기획재정부 고시 하나뿐이라 `source` 열은 두지 않았다. 관세청 과거 스냅샷 같은
다른 출처가 생기면 그때 추가한다.

```sql
-- 폐지코드를 포함해 아무 HS10이나 이름을 얻는다(가장 최근 판본 우선)
SELECT h.hs10, h.name_ko
FROM dim_hs10_name_hist h
QUALIFY ROW_NUMBER() OVER (PARTITION BY h.hs10 ORDER BY h.byeolpyo_year DESC) = 1;
```

#### 완성도

- **출처 교차 확인.** 관세청 `dim_hs10`과 2022년 별표가 겹치는 11,267종에서 품명이
  **98.5% 일치**한다. 출처가 달라도 같은 값을 준다.
- (hs10, 별표연도) 중복 0행, 빈 국문 품명 2행.
- 쪽번호 오염 0건(§3.4 파서 수정 반영). 검사 패턴에 걸리는 유일한 코드는
  3908101000 '폴리아미드 -6'인데 이는 나일론 6의 정식 품명이다.

#### 한계

1. **덮지 못하는 456종**은 대부분 2011년 이전에 폐지된 코드다. 별표가 2011년부터라
   그 이전에 사라진 것은 품명을 얻을 수 없다(§3.4의 같은 제약).
2. **연 단위 스냅샷이다.** 별표가 없는 해(2012·2014·2016·2018~2020·2023~)의 품명 변경은
   앞뒤 판본 사이 어딘가에서 일어난 것으로만 알 수 있고 정확한 시점은 모른다.
3. **관세청 품명과 다를 수 있다.** 위 98.5%의 나머지 1.5%가 그렇다. 두 기관이 같은
   코드에 조금 다른 문자열을 쓴 것이므로, 관세청 표기가 필요하면 `dim_hs10`을 쓴다.

## 5. 무결성 검증 (재구축 후 필수)

1. fact_trade 금액 합 = fact_total 금액 (같은 yyyymm×stat_cd)
2. bal_payments = exp_dlr - imp_dlr (전 행)
3. yyyymm(파일명) = year 필드(YYYY.MM) 일치
4. 시간 연속성 (200701~최신월 빠진 월 없음)
5. fact.stat_cd → dim_country 매칭률 (미매칭 코드 목록화)
6. fact.hs10 → dim_hs10 매칭률 (폐지 코드로 인한 미매칭 목록화)
7. SUBSTR(hs10,1,6) → dim_hs6_concordance 커버리지
검증은 단일 스크립트(04_validate.py) 하나로 통합한다. v1처럼 검증을 여러 버전 파일로 분열시키지 않는다.
현재 결과: PASS 9, WARN 4, FAIL 0 (2026-08-28 재실행, HS10 테이블 추가 후에도 동일).

**HS10 계층(2026-08-28 추가)의 검증은 04에 넣지 않고 만드는 스크립트가 스스로 한다.** 연계·품명은
